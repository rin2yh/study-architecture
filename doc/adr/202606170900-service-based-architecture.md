# ADR-202606170900: サービスベースアーキテクチャを採用する

- Status: Accepted (target style は ADR-[[202607011621]] でマイクロサービスへ段階移行中)
- Date: 2026-06-17

## Context

『アーキテクチャの基礎』(Mark Richards & Neal Ford) のサービスベースアーキテクチャを学習する題材として
EC サイトを構築する。マイクロサービスのような細粒度・DB 完全分離の複雑さを最初から背負わず、
「素直に立ち上げて改善で育てる」方針を取りたい。

## Decision

スタイルとして **サービスベースアーキテクチャ** を採用する。決め手は「サービスが**粗粒度**
（coarse-grained）であること」。ドメイン単位の 5 サービス（product / order / payment / member / shipping）に
分割する。

- 各サービスは 1 コンテナ・個別デプロイ。内部は `internal/` で閉じる。
- UI もドメイン分割し、出発点は UI → サービスの**直接呼び出し**。

改善は「共有 DB (schema 分離) → UI 入口の集約 → データ所有権の確定 → 結合の弱い縁から DB 分割」の順に
段階を踏む。各段は後続 ADR で具体化する（DB 分割の進め方は ADR-[[202606240522]]）。

## Consequences

- 粗粒度ゆえにサービス間通信が少なく、共有 DB と組み合わせて初期の複雑さを抑えられる。
- 個別デプロイ可能だが、データは当面共有するため真の独立性は段階的に獲得する。
- マイクロサービスへ進化させる余地を残す（フロント選定 ADR-[[202606170904]] もこれを見据える）。

## Alternatives considered

- **モノリス**: 学習目的（サービス分割の体験）に合わない。
- **マイクロサービス**: 細粒度・DB 分離・分散の複雑さを最初から負うことになり方針に反する。
