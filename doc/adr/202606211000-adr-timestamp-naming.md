# ADR-202606211000: ADR の識別子を連番からタイムスタンプ (YYYYMMDDHHmm) に変える

- Status: Accepted
- Date: 2026-06-21
- Supersedes: これまでの連番採番 (`NNNN-slug.md`) 規約
- Relates to: `.claude/rules/comments.md` (ADR 参照の書式), `README.md` (ADR リンク)

## Context

- 4 桁連番では次番号を採るのに既存の最大番号が要り、ブランチを分けて並行に起こすと両方が同じ番号を選ぶ。
  Git は別ファイル名どうしを衝突として検出しないので、マージが通って**重複番号が黙って残る**。
- 実際に `0014` と `0016` が重複しており、`[[NNNN]]` 参照の宛先が曖昧になっていた。
- 採番の調停を**作成時点で不要**にしたい。

## Decision

**識別子をファイル名先頭の作成日時タイムスタンプ `YYYYMMDDHHmm` にする。** ファイル名は
`YYYYMMDDHHmm-slug.md`、相互参照は `ADR-[[YYYYMMDDHHmm]]`。

- **粒度は分**。日付のみだと同日 2 件目でまた衝突する。分なら人手で同一分に 2 件起こす状況はまず無く、
  起きても 1 分ずらせば済む。秒は識別子を伸ばす割に衝突確率が実用上変わらない。
- **参照に `ADR-` 接頭辞を付ける**。12 桁の数字列だけでは何の ID か読み取れないため。
- 既存 18 件も改名して統一する (ID は各 ADR の `Date:`、同日内は元の連番順に分を割り当て)。重複していた
  `0014` / `0016` もこれで別 ID になる。本文・コメント・README・フックのプロンプトまで参照を追従させた。

## Consequences

- **作成時の番号調停が消える**。並行作成でも分が違えば自然に一意で、連番由来の衝突が原理的に起きない。
- **識別子から作成順が読める**。連番は採番タイミングで前後し得たが、タイムスタンプは作成日時そのもの。
- **参照が長くなる** (`[[0008]]` → `ADR-[[202606190900]]`)。可読性は接頭辞で補う。
- **過去 ID への外部リンクが切れる**。学習用リポジトリで影響は許容。今後は改名を避け、Superseded でも
  ファイル名は据え置く。

## Alternatives considered

- **連番のまま運用ルールで衝突回避** — 人間の規律に頼る方法は、まさにそれが破れて重複が出ている。
- **短い安定 ID を別に持つ (`ADR-19` 等)** — 参照は短いが、その短 ID の採番でまた調停が要る。
- **slug で参照する** — 読みやすいが、slug の改名で参照が全部切れる。タイトル変更は ADR 更新の常。
- **秒粒度** — 分粒度で衝突はほぼ消えており、対価が薄い。
