# ADR-202608150835: ブローカをポートで隔離し、アプリからベンダ API を見せない

- Status: Accepted
- Date: 2026-08-15
- Relates to: ADR-[[202608150830]] (マネージドキュー前提), ADR-[[202606300600]] (outbox)

## Context

- ADR-[[202608150830]] でクラウドのマネージドキューを前提にしたため、そのままでは AWS / GCP の
  SDK 型が consumer と outbox リレーに直接入る。
- 乗り換えの可能性は現実にある (AWS と GCP の両方を候補にしている)。SDK が散らばると、そのとき
  触る箇所が全 consumer に広がる。

## Decision

publish / subscribe をアプリ側のインターフェース (ポート) で定義し、SQS / Pub/Sub の実装をアダプタに置く。
ハンドラはブローカの型を知らない。

- 決め手は乗り換え時の変更範囲。ポートを 1 枚挟めば、差し替えはアダプタに閉じる。
- 既存の `outbox.Event` / `outbox.Store` が同じ理由でブローカ非依存に作られており、その延長で揃う。

## Consequences

- 乗り換えはアダプタの追加で済み、consumer とハンドラは触らない。ローカルの kumo も同じアダプタで動く。
- 抽象の分だけ間接参照が増える。ブローカ 1 つしか使わない間は「無駄な 1 枚」に見える。
- ブローカ固有の概念はポートに滲む。順序保証のキー (SQS の `MessageGroupId` / Pub/Sub の ordering key) は
  ポートの引数に出さざるを得ない。

## Alternatives considered

- **SDK を直接使う** — 最短で、型変換も要らない。乗り換え時に全 consumer を書き換えることになる。
- **CloudEvents などの共通仕様に寄せる** — 相互運用の枠組みまで得られるが、購読者が同一リポジトリに
  閉じている現状では、封筒の仕様と変換コストが釣り合わない。
